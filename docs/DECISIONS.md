# 아키텍처 및 방법론 결정 기록 (ADR)

각 기록은 결정, 이유, 기각한 대안, 그리고 이 결정이 틀렸음을 어떻게 드러낼 수 있는지를
명시합니다. 과학적 주장에 영향을 주는 결정은 그것을 반증할 테스트나 실험을 함께 지목합니다.

## ADR-0001 — 소스 레이아웃·버전 고정·락파일을 갖춘 Python 3.12
**상태:** 채택 (2026-08-16)

**맥락.** 호스트 기본 인터프리터는 3.9.13이지만, numpy(2.5.2)·scipy(1.18.0)·librosa 현행
릴리스는 3.12 이상을, pandas·scikit-learn·matplotlib은 3.11 이상을 요구합니다.
Homebrew로 Python 3.12.9를 사용할 수 있습니다.

**결정.** `>=3.12,<3.14`를 타깃으로 합니다. 테스트가 작업 트리가 아니라 설치된 패키지를
임포트하도록 `src/` 레이아웃을 씁니다. `pyproject.toml`에 정확한 버전을 고정하고
`requirements.lock`을 동결합니다.

**기각.** 3.9 지원 — 구버전 numpy/scipy를 강제해 재현성 목표를 무력화합니다.

**재검토 조건:** 필수 의존성이 3.12 지원을 중단할 때.

## ADR-0003 — 외부 데이터 출처는 산문이 아니라 라이브 API에서 검증
**상태:** 채택 (2026-08-16)

**맥락.** `docs/DATA_REGISTRY.md`가 라이선스와 행 수를 서술합니다. 산문은 현실과 어긋날 수
있습니다.

**결정.** `data/sources.yaml` 작성 전에 각 출처의 라이브 메타데이터 API를 조회하고,
**실제로 관측한 값**을 기록했습니다. 다음 두 건의 불일치를 포함합니다.

1. **1차 코퍼스의 메타데이터 파일은 `updated_metadata.csv`가 아니라 `metadata.csv`입니다.**
   데이터셋 카드 산문은 전자를 지칭하나, 저장소의 실제 파일 목록(729개: `.gitattributes`,
   `README.md`, `metadata.csv`, `audio_files/*.wav` 726개)에는 후자만 존재합니다.
   레지스트리가 실제 이름을 고정하고 코드는 레지스트리에서 읽습니다.
2. **Zeroth-Korean 미러에 기계 판독 가능한 `license` 필드가 없습니다.**
   `cardData.license`가 부재합니다. CC BY 4.0은 카드 *본문*과 상위 OpenSLR SLR40에
   명시되어 있습니다. 레지스트리는 라이선스와 함께 **기계 판독 태그가 없다는 사실**을
   기록해 감사 가능하게 합니다.

**귀결.** `data/sources.yaml`은 출처별 `verified_at` 날짜를 갖고, Zenodo 페처는 다운로드
시점에 라이브 라이선스를 재확인합니다. 라이선스 변경은 조용한 승계가 아니라 **하드 에러**입니다.

## ADR-0004 — 문헌의 축소 목록이 아닌 정서법상 전체 자모 목록 사용
**상태:** 채택 (2026-08-16)

**맥락.** Ma et al. (2026, DOI 10.21848/asr.250216)은 초성 18·중성 16·종성 8을 분석합니다.
AUDIRE는 그들의 자극 집합이 아니라 임의의 한국어 자막 텍스트를 채점해야 합니다.

**결정.** 혼동행렬은 현대 정서법 전체 목록을 사용합니다: 초성 19(무음 초성 `ㅇ` 포함),
중성 21, 종성 27 + 명시적 `NO_CODA` 범주. `audire.confusion.grouping`이 출판된 표와
비교할 때 필요한 7종성 중화 매핑을 제공합니다.

**일관성 검사.** 초성 19 − 무음 초성 = **18**로 Ma et al.의 초성 수와 일치.
중화된 표면 종성 7 + `NO_CODA` = **8**로 그들의 종성 수와 일치. 중성 16이라는 수치는
본 과제가 접근 가능한 자료로는 재구성할 수 없어, 추측 대신 `docs/RESULTS.md`에 미해결로
기록합니다.

**반증 가능성:** 축소 목록이 홀드아웃 오청 예측을 더 잘한다는 근거가 나오면 기각됩니다.
`with_smoothing`/`grouping`이 그 절제 실험을 저렴하게 만듭니다.

## ADR-0005 — 독립적인 오류 분류체계, 명시적으로 재구현이 아님
**상태:** 채택 (2026-08-16)

**맥락.** Joo et al. (2026)은 오류를 10범주로 코딩합니다. 코딩 매뉴얼은 본 과제가 접근할 수
없습니다.

**결정.** AUDIRE는 정서법 분해로부터 자체 분류체계(정반응/대치/탈락/첨가/복합/무응답)를
정의하고, 그 빈도가 해당 논문과 **호환되지 않음**을 문서화합니다. 초성의 `ㅇ`은 음운론적
무음 초성이므로 `ㄱ→ㅇ`은 탈락, `ㅇ→ㄱ`은 첨가입니다. 종성의 탈락·첨가는 일반적인
`NO_CODA` 전이입니다.

**귀결.** AUDIRE의 어떤 출력도 출판된 오류율 표를 재현했다고 제시할 수 없습니다.

## ADR-0006 — 명시적·직렬화 가능한 사전분포를 갖는 디리클레 사후평균 평활
**상태:** 채택 (2026-08-16)

**맥락.** 25문항 교정으로는 19×20 초성 행렬 대부분을 관측할 수 없습니다. 평활하지 않은
행은 퇴화(0 또는 1)하고 미관측 행은 정의되지 않습니다.

**결정.** 행 *i*를 `(n_ij + α·π_ij) / (n_i + α)`로 추정합니다. `α`는 총 유사빈도,
`π_i`는 합이 1인 명시적 사전분포 행입니다. 기본값은 `α = 1.0` + 균등 사전분포입니다.
집단 프로파일이 있으면 `SmoothingSpec(kind="explicit", prior=group)`이 집단 쪽으로
계층적 축소를 수행합니다.

**기각.** 셀마다 1을 더하는 라플라스 평활 — 열이 20~28개이므로 유사빈도 20~28개를 주입해
25시행 교정을 압도합니다.

**안전장치.** `α = 0`에 미관측 행이 있으면 `NaN` 대신 예외를 던집니다. 빈도는 절대
버려지지 않아 `p_correct`와 `n_observations`를 항상 함께 조회할 수 있습니다.
미관측 행은 `unobserved_targets`와 `coverage`가 보고합니다.

## ADR-0007 — 라이선스로 잠긴 1차 코퍼스 없이도 시스템이 동작해야 함
**상태:** 채택 (2026-08-16)

**맥락.** 1차 코퍼스는 CC BY-NC-ND 4.0이고 카드가 사용 전 제작자 통보를 요청합니다.
AUDIRE가 자동화해서는 안 되는 사람 단계이므로, 신규 평가자에게 음원이 없을 수 있습니다.

**결정.** 두 번째 자극 출처를 함께 제공합니다: 한글 자모 목록 자체에서 생성한 결정론적
음소 균형 설계(19 × 21 × 8 = 3,192 조합을 서로소 순환 순서로 방문하므로 앞 *k*개가 곧
균형 잡힌 *k*문항 목록). 제3자 라이선스가 없습니다. 웹 클라이언트가 브라우저의 한국어
음성합성으로 재생합니다.

**모든 보고서에 명시할 제약.** 브라우저 음성합성은 **음압 교정이 되어 있지 않습니다.**
이를 이용한 교정은 연구·접근성 측정이며 결코 임상 측정이 아닙니다. 사람 단계가 완료되면
녹음 코퍼스가 여전히 선호되는 출처입니다.

## ADR-0008 — 혼동 프로파일을 임상 프로파일과 구조적으로 분리
**상태:** 채택 (2026-08-16)

**맥락.** RQ1은 `C_u`가 PTA/SRT/WRS를 넘어 정보를 더하는지 묻습니다. 둘을 하나의 객체나
하나의 점수로 합치면 이 질문 자체가 성립하지 않습니다.

**결정.** `HearingProfile`(청력·어음 점수)과 `ConfusionProfile`(행렬 3개)은 별개 타입이며
별개로 영속화됩니다. 이를 소비하는 특징 빌더도 개별적으로 켜고 끌 수 있어, 필수 절제
4개 arm이 코드 수정이 아니라 문자 그대로 설정이 됩니다.

**반증.** 결합 arm이 홀드아웃 청취자 수준 데이터에서 임상 단독 arm을 결코 이기지 못하면
RQ1은 음성으로 답해진 것이며 그렇게 보고해야 합니다.

## ADR-0010 — ASR 불확실성은 청취자 오청 위험과 별개 채널
**상태:** 채택 (2026-08-16)

**맥락.** `AGENTS.md` §9: 잘못된 ASR 가설이 청취자가 오청할 것이라는 근거가 되어서는
안 됩니다.

**결정.** `WordRisk`는 `asr_confidence`와 `listener_risk`를 별개 필드로 보유하며,
자막 정책은 **오직 `listener_risk`로만** 순위를 매깁니다. ASR 신뢰도는 설명과 JSON
내보내기에 노출되고, 종단 평가는 ASR WER을 오청 예측 오류와 분리해 보고합니다.

ASR 신뢰도가 낮아 표시된 단어는 `SHOWN_LOW_ASR_CONFIDENCE`라는 **구별되는 결정값**을
받으므로, 자막 연구 채점 시 개인화 적중으로 계산될 수 없습니다.

백엔드가 신뢰도를 제공하지 않으면 값은 `None`이며 **절대 조작된 기본값이 아닙니다.**
조작된 신뢰도는 이 분리 자체를 무의미하게 만듭니다.

## ADR-0011 — 자막 예산은 청취자별 적용이 1차, 통합은 메커니즘 대조
**상태:** 채택 (2026-08-16, RQ2 결과에 따라 추가)

**맥락.** 초기 RQ2 분석은 총합 오청 재현율만 보고했습니다. 청취자별 예산과 통합 예산이
전혀 다른 답을 준다는 것이 드러났습니다.

**결정.** `select_budget()`이 두 모드를 모두 지원하고 두 결과를 항상 함께 보고합니다.
`recall_by_listener()`가 청취자별 재현율 분포를 반환합니다.

**이유.** 청취자 내부에서 상수인 특징(PTA·SRT·WRS)은 그 청취자의 단어를 직접 구별할 수
없습니다. arm을 별도로 적합하면 단어 특징 계수가 달라져 작은 간접 차이는 생길 수 있지만,
통합 예산에서처럼 청취자 수준 자체를 직접 순위화할 수는 없습니다. 통합 예산은 강력하지만
**최하위 청취자의 재현율을 0.000으로** 만듭니다. 총합 지표만으로는 이것이 큰 승리로
보고됩니다.

**귀결.** `docs/RESEARCH_PLAN.md`가 지정한 1차 성과지표는 그 자체로 불충분하며,
청취자별 재현율 분포가 공동 1차 지표여야 합니다. 이를 조용히 수정하지 않고 발견으로
기록했습니다(`docs/RESULTS.md` §4).

## ADR-0012 — 최종 모델은 경험적 근거로 선택된 로지스틱 회귀
**상태:** 채택 (2026-08-16, `rq1_main` 5시드 결과에 따라)

**맥락.** 연구 계획은 "AI처럼 보이게 하려고 딥러닝을 쓰지 말 것"과 "최종 모델은 경험적
근거로 선택할 것"을 요구합니다.

**결정.** 로지스틱 회귀(L2, `C=1.0`)를 1차 모델로 채택합니다.

**근거.** 정당화된 비선형 비교 모델(히스토그램 그래디언트 부스팅)이 **모든 arm에서**
로지스틱 회귀와 같거나 낮았습니다. 최선 arm의 5시드 평균 PR-AUC는 0.6617 대 0.6685입니다.
따라서 복잡도를 지불할 이유가 없고, 해석 가능한 계수를 얻습니다.

**재검토 조건:** 실제 참여자 데이터에서 표본 크기가 크게 늘어나 비선형 상호작용을
지지할 때. 실행기가 모든 결과에 학습 크기를 기록하므로 과적합된 비선형 승리는 가시적입니다.

## ADR-0013 — 기본 ASR 가중치는 불변 모델 리비전에 고정
**상태:** 채택 및 실제 실행 검증 (2026-08-16)

**맥락.** `faster-whisper`에 `model_id="small"`만 전달하면 Systran 모델 저장소의 움직이는
기본 브랜치를 따라갑니다. 패키지 버전이 같아도 다른 가중치를 받을 수 있으므로, 모델 버전을
기록한다는 시스템 계약을 충족하지 못합니다.

**결정.** 기본 모델 `Systran/faster-whisper-small`을 Hugging Face 커밋
`536b0662742c02347bc0e980a01041f333bce120`에 고정합니다. 백엔드는 이 값을 로더의
`revision` 인자로 전달하고 모든 전사 provenance에 `model_revision`을 기록합니다. 다른
모델을 선택하면 호출자가 그 모델의 리비전을 명시할 수 있습니다.

**검증.** `faster-whisper==1.2.1`, CTranslate2 CPU `int8`, 위 가중치와 매니페스트 다이제스트
`0b69ffa52399a9be…`의 Zeroth-Korean test 전용 매니페스트 음성을 함께 실행했습니다. WAV에서 비어 있지 않은
한글 타임스탬프 토큰과 결함 없는 시간 순서를 얻었고, 같은 음성의 MP3·MP4 입력도
통과했습니다. 이 검사는 실제 추론을
요구하므로 `AUDIRE_RUN_REAL_ASR=1`에서만 실행됩니다. 이 최초 스모크 자체에는 정확도 주장을
붙이지 않았고, 이후 별도 E7 고정 10화자 실행에서 WER/CER를 측정했습니다(`docs/RESULTS.md`
§7).

**출처.** Hugging Face 모델 API
<https://huggingface.co/api/models/Systran/faster-whisper-small> 및 faster-whisper 1.2.1

## ADR-0014 — 배포 모델은 명시적으로 빌드하고 검증된 로컬 아티팩트만 로드
**상태:** 채택 및 로컬 실행 검증 (2026-08-16)

**맥락.** G6 서버가 `WordScorer`를 필요로 하지만, 연구 실행의 out-of-fold 예측은 배포용
단일 적합 모델이 아닙니다. 서버 시작 때 임의 합성 모델을 조용히 적합하거나, 모델이 없을 때
가짜 점수를 반환하면 같은 입력이 숨은 상태에 따라 달라지고 합성 근거가 실제 효능처럼 보일
수 있습니다. 또한 joblib은 pickle 직렬화 모델을 사용하므로 신뢰하지 않는 파일을 로드하면
임의 코드 실행 위험이 있습니다.

**결정.** `make model`만 배포 모델을 만듭니다. ADR-0012에서 선택된 L2 로지스틱 결합 arm을
`rq1_main.yaml`의 5개 시드 전체(독립 합성 청취자 실현 400개, 단어 시행 100,000개)에 다시
적합합니다. 이 전체 적합 자체에는 홀드아웃 성능 주장을 붙이지 않고, 성능 주장은 별도로
기록된 청취자 수준 OOF 평가만 사용합니다.

아티팩트는 `private/models/`에 두며 커밋하지 않습니다. JSON sidecar가 합성 학습 출처,
임상 효능 주장 없음, 설정 SHA-256, 시드, git SHA/더티 상태, 락 해시, 데이터 매니페스트,
모델 버전과 아티팩트 SHA-256을 기록합니다. 서버는 sidecar와 체크섬·스키마·버전·적합 상태가
모두 맞는 **로컬 생성 파일만** 읽습니다. 모델이 없으면 health가 준비되지 않았다고 보고하고
처리 API는 503을 반환합니다. 신뢰 경계를 넘어 받은 joblib 파일은 체크섬이 있더라도 로드하지
않습니다.

**검증.** 저장/복원, 변조 체크섬, 미적합 모델 거부 테스트와 신선한 Python 프로세스 로드
검사를 통과했습니다. 실제 로컬 아티팩트는 `git_dirty: true`를 정직하게 기록하므로 최종
릴리스 전 깨끗한 SHA에서 다시 생성해야 합니다.

**출처.** joblib 1.5.3 persistence 문서
<https://joblib.readthedocs.io/en/stable/persistence.html> (접근일 2026-08-16): joblib 로드는
pickle 모델 기반이며 신뢰하지 않는 출처의 객체를 로드하지 말라고 명시합니다.

## ADR-0016 — 부류 상호작용 특징은 음운 분류표에서 파생하고 "증거 없음"을 약점으로 취급하지 않는다
**상태:** 채택 (2026-08-16, Phase D17)

**맥락.** 기존 혼동 블록(16개 집계)은 "이 청취자가 전반적으로 얼마나 나쁜가"를 요약하며 이는
WRS와 대체로 중복됩니다. 청취자별 자막 예산이 실제로 필요로 하는 신호는 "이 청취자에게 이
단어가 유난히 위험한가"이고, 그 신호는 `약점(청취자, 부류) x 포함비율(단어, 부류)` 상호작용에
있습니다. 구현 과정에서 두 개의 실제 결함이 드러났습니다.

첫째, 부류 목록을 손으로 나열하면서 공명음 발성유형(유음/비음/무초성)을 빠뜨렸고,
`ㄴ/ㄹ/ㅁ/ㅇ` 로 시작하는 모든 단어가 `KeyError` 로 실패했습니다.

둘째, 그리고 더 중요하게, 부류 약점을 "모든 구성원의 평활된 `p_correct` 평균(가중치 n+1)"으로
계산했습니다. 균일 사전분포에서 미관측 target 의 `p_correct` 는 1/20 ≈ 0.05 이므로, **한 번도
제시되지 않은 부류가 오류율 0.95 로 집계되어 실제로 25/30 을 틀린 부류(0.84)보다 더 약한 것으로
나왔습니다.** 25회 교정에서는 대부분의 부류가 미관측이므로, 이 인공물이 상호작용 항 전체를
지배하고 "어떤 음소가 우연히 표집되었는가"를 개인 신호로 착각하게 만들었을 것입니다.

**결정.** 부류 목록은 `ONSET_MANNER`/`ONSET_PHONATION`/`NUCLEUS_SHAPE` 분류표에서 파생합니다
(6+6+4개, 종성은 7종 대표음 + 무종성 8개, 상호작용 24항, 블록 전체 59열). 약점 추정은 **관측된
증거만** 가중하고, 증거가 없는 부류는 그 청취자의 전체 오답률로 후퇴하며, 관측이 전혀 없는
청취자는 0.5(최대 무정보)를 받습니다. 미관측 행에 모집단 정보를 넣는 원리적 처방은
ADR-0017 의 집단 사전분포 축소이고, 둘은 함께 작동합니다.

**이전 결과 영향.** **이전 결과는 영향받지 않습니다.** `confusion_rich` 블록과 이를 사용하는
두 arm(`confusion_rich_only`, `clinical_plus_confusion_rich`)은 이번 Phase D 에서 처음 도입되었고,
기록된 RQ1/RQ2/RQ3/E11 실행은 모두 기존 `confusion` 블록만 사용합니다. 기존 블록의 의미론은
바뀌지 않았고 기존 arm 정의도 그대로입니다.

**검증.** 모든 초성 x 모든 중성 조합에서 전체 길이의 특징 벡터가 나오는지 확인하는 전수
회귀 테스트, 미관측 부류가 측정된 약점보다 낮게 나오는지 확인하는 회귀 테스트, 상호작용이
두 반쪽의 곱과 정확히 일치하는지 확인하는 테스트를 포함해 22개 테스트가 통과했습니다.

## ADR-0017 — 집단 사전분포 축소는 폴드마다 훈련 청취자만으로 재적합하며, 그 사실을 산출물이 증명한다
**상태:** 채택 (2026-08-16, Phase D18)

**맥락.** 25회 교정으로는 19x20 초성 행렬의 대부분을 관측할 수 없습니다. 균일 사전분포에서
미관측 행은 모두 같은 평평한 분포가 되어, "어떤 혼동이 흔한가"에 대해 모집단이 이미 알고 있는
것을 전부 버립니다. 각 청취자를 집단 사전분포로 축소하면 그 정보를 쓰면서도 잘 관측된 음소는
개인 추정값에 머무를 수 있습니다.

위험은 명백합니다. 홀드아웃 청취자를 포함한 **전체 코호트**에서 사전분포를 적합하면 그들의
응답이 학습 표현 안으로 들어가고, 모든 홀드아웃 지표가 부풀려집니다. 청취자 단위 그룹 분할은
이 누출을 전혀 잡지 못합니다 — 행은 여전히 완벽하게 분리되어 있기 때문입니다.

**결정.** `fit_group_prior` 는 넘겨받은 프로파일만 사용하고 기여자 목록을 `fitted_from` 에
기록합니다. `evaluate_arm(group_shrinkage=True)` 는 **폴드마다** 훈련 청취자만으로 사전분포를
다시 적합하고(그래서 그 모드에서는 설계 행렬도 폴드마다 다시 만듭니다), 새 가드
`assert_prior_fitted_on_train_only` 로 사전분포 기여자와 홀드아웃 청취자의 교집합이 비어 있음을
확인하며, 폴드별 기여자 목록을 `model_description["group_shrinkage"]` 에 남겨 사후 감사가
가능하게 합니다. 기본값은 꺼짐이므로 기존 실행의 의미론은 바뀌지 않습니다.

**이전 결과 영향.** **이전 결과는 영향받지 않습니다.** 축소는 새 기능이고 기본값이 꺼짐이며,
기록된 어떤 실행도 이 경로를 통과하지 않았습니다.

**검증.** 폴드별 기여자 집합이 훈련 청취자 집합과 정확히 일치하고 홀드아웃과 교집합이 없음을
확인하는 테스트, 전체 코호트 사전분포가 가드를 발동시키는 테스트, 축소가 행 정렬을 깨지
않는 테스트를 포함해 15개 테스트가 통과했습니다.

## ADR-0018 — EBM 대신 스플라인 GAM, 그리고 랭킹 모델의 행 순서는 내용 해시로 정준화한다
**상태:** 채택 (2026-08-16, Phase E20/E21)

**맥락.** 미션은 해석 가능한 비선형 반응 곡선과 **통제된** 수의 상호작용을 요구합니다.
Explainable Boosting Machine(`interpret`)이 표준 선택이지만, 독립 청취자 약 80명 규모에 무거운
의존성을 추가하는 비용이 이득보다 큽니다.

랭킹 모델에서는 더 미묘한 문제가 있었습니다. LightGBM 의 `group` 인자는 행이 질의별로 연속
배치되어 있다고 가정하므로 청취자로 정렬하는 것까지는 자명합니다. 그러나 **그룹 내부** 순서는
호출자에게 달려 있고, LambdaMART 는 고려하는 쌍을 잘라내기(truncation) 때문에 그 순서가 적합
결과를 바꿉니다. 16명 코호트에서 훈련 행을 섞었더니 청취자내 Spearman 상관이 0.86 까지
떨어졌습니다 — 부동소수점 잡음으로 넘길 수 없는 크기이고, 고정 예산에서 선택되는 단어가
달라집니다.

**결정.** `SplineTransformer`(n_knots=5, degree=3) + 명시적으로 나열된 6개의 2원 상호작용 +
L2 페널티 로지스틱 회귀로 GAM 을 구성합니다. 상호작용 목록이 짧고 이름으로 적혀 있다는 사실
자체가 고용량 적합을 막는 장치입니다. 랭킹 모델은 `(행 내용, 라벨)` 의 blake2b 다이제스트로
청취자 내부를 정렬해, 적합 결과가 훈련 예제의 **집합**에 대한 결정적 함수가 되게 합니다.
`hash()` 는 프로세스마다 salt 가 달라 재현성을 조용히 깨므로 쓰지 않습니다.

랭킹 점수는 확률이 아닙니다. `describe()` 가 `output_is_probability: False` 를 보고하고,
임계값 정책이 소비하기 전에 청취자 홀드아웃 데이터에서 교정해야 합니다.

**이전 결과 영향.** **이전 결과는 영향받지 않습니다.** 세 모델(`residual`, `spline_gam`,
`lambdamart`) 모두 이번에 새로 추가되었고 기록된 실행은 로지스틱/그래디언트 부스팅/음소
독립 기저선만 사용했습니다. 로지스틱 회귀는 ADR-0012 에 따라 기본 참조 기저선으로 남습니다.

**검증.** 서로 다른 두 순열에서 예측이 비트 단위로 동일함을 확인하는 테스트, PYTHONHASHSEED 를
바꾼 별도 프로세스에서 정준 순서가 같음을 확인하는 테스트, 질의 그룹 수가 청취자 수와 정확히
일치함을 확인하는 테스트를 포함해 33개 테스트가 통과했습니다.

## ADR-0019 — 참조 대비 판정은 시드별 짝지은 비교로 하고, 교정은 요청과 실제를 따로 기록한다
**상태:** 채택 (2026-08-16, Phase E22/E23)

**맥락.** 두 개의 보고 결함이 실제 실행에서 드러났습니다.

첫째, 교정기가 폴백할 때 `self.method` 를 `"none"` 으로 덮어썼습니다. 그러면 요청이
무엇이었는지에 대한 유일한 기록이 사라져, **의도적으로 교정을 쓰지 않은 실행**과 **교정이
조용히 실패한 실행**을 산출물만으로 구분할 수 없습니다. 게다가 `name` 은 여전히
`"logistic+platt"` 였으므로 기록이 스스로 모순됐습니다. 교정 방법 비교가 E22 의 질문
자체인데, 질문을 잊어버린 산출물로는 답할 수 없습니다.

둘째, 그리고 더 심각하게, 후보가 참조 기저선을 이겼는지를 **평균끼리 비교**해 판정했습니다.
E23 축소 A/B 에서 평균 차이 **+0.0006** 이 "새 계열이 참조를 이겼다: True" 로 보고됐는데,
같은 데이터의 시드별 짝지은 차이는 10개 중 6개만 양수인 사실상 동전 던지기였습니다. 이는
"승리를 만들어내지 말라" 는 원칙을 직접 위반하는 보고 규칙이었습니다.

**결정.** 교정은 `method`(요청)를 보존하고 `effective_method` / `fell_back` /
`fallback_reason` / `n_calibration_listeners` 로 실제를 기록하며, `evaluate_arm` 이 이를
**폴드마다** 남깁니다. 교정기는 어떤 폴드에서 폴백하고 다른 폴드에서 성공할 수 있으므로,
루프 끝의 스냅숏 하나는 마지막 폴드를 전체인 양 보고합니다.

참조 대비 판정은 **시드별로 짝지어** 합니다. 같은 시드는 같은 합성 코호트를 뜻하므로 두
모델을 같은 청취자 위에서 짝지을 수 있고, 짝지으면 코호트 간 변동이 상쇄되어 남는 것이
모델 차이입니다. 판정 불리언은 **모든 시드에서 이길 것**을 요구하고, 짝지은 차이의
평균·표준편차·우세 시드 수를 함께 보고합니다.

**이전 결과 영향.** **기록된 이전 결과는 영향받지 않습니다.** 기록된 RQ1/RQ2/RQ3/E11
실행은 모두 `calibration: none` 이라 폴백 경로를 통과한 적이 없고, 참조 대비 판정은 E22
에서 처음 도입된 지표입니다. E22 실행(`e98abb4`)은 수정 전 코드로 시작되었으나, 같은
`model_comparison_rows.json` 에 수정된 요약기를 적용해 대조한 결과 **판정은 동일**하고
(최고 후보가 곧 참조 기저선), 표에서 달라진 필드는 표기용 `effective_methods` 하나뿐이며
지표는 하나도 바뀌지 않았습니다. 기록된 산출물은 손대지 않았고 재실행하지 않았습니다.

**검증.** 폴백이 요청 방법을 보존하는지, 재적합이 이전 폴백 상태를 지우는지, 교정 기록이
폴드마다 남는지, 그리고 "평균으로는 이기지만 짝지으면 4개 중 1개 시드에서만 우세한" 합성
사례에서 판정이 False 가 되는지를 확인하는 테스트를 포함해 23개 테스트가 통과했습니다.

## ADR-0020 — run_id 는 충돌할 수 없어야 하고, 레지스트리 쓰기는 원자적이며, 아티팩트는 다이제스트를 남긴다
**상태:** 채택 (2026-08-17, Phase F)

**맥락.** 레지스트리에서 세 가지 결함이 확인됐습니다.

첫째이자 가장 심각한 것: `run_id` 가 `실험명-초단위시각-짧은sha` 였습니다. 같은 실험을 같은
초에 두 번 시작하면 id 가 같아지는데, `append_row` 는 run_id 로 기존 항목을 **제거하고**
새 항목을 붙입니다. 실측으로 확인했습니다 — 두 실행을 기록했더니 레지스트리에 한 건만 남고
먼저 끝난 실행의 설정·지표·상태가 흔적 없이 사라졌습니다. 이는 "실패한 실험이 사라지지
않는다"는 중단 조건을 직접 위반합니다. 빠른 설정, 스크립트 루프, 병렬 호출에서 충분히
도달 가능합니다.

둘째: `registry.yaml` 과 아티팩트를 `write_text` 로 썼습니다. 이는 대상 파일을 먼저 비우므로
쓰기 도중 실패하면 잘린 파일이 남습니다. 레지스트리의 경우 **모든 실행의 기록**을 한꺼번에
잃는다는 뜻입니다.

셋째: 실행 기록이 아티팩트의 **경로만** 남기고 내용은 남기지 않았습니다. 파일이 생겼다는
사실은 알지만 무엇이 들었는지는 모르므로, 사후에 편집된 결과 파일과 실행이 실제로 만든
파일을 구분할 수 없습니다.

**결정.** `run_id` 에 `secrets.token_hex(3)` 무작위 접미사를 붙여 유일성을 보장합니다.
더불어 `append_run` 은 같은 run_id 인데 `started_at_utc` 가 다르면 `RegistryCollision` 을
올리고 **덮어쓰지 않습니다** — 접미사가 있어도 방어선을 하나 더 둡니다. 실행 자신의 생명주기
(running → completed)는 `started_at_utc` 가 같으므로 정상적으로 갱신됩니다.

레지스트리와 아티팩트 쓰기는 임시 파일 + `os.replace` 로 원자화합니다.

`save_artifact` 는 쓰는 순간의 SHA-256 을 `artifact_digests` 에 기록하고,
`verify_artifacts(run_id)` / `audire verify-runs` 가 다시 해싱해
`match` / `modified` / `missing` / `not_recorded` 를 보고합니다. 수정이나 누락이 있으면
CLI 가 종료 코드 1 을 냅니다. `artifact_digests` 는 `artifacts` 를 재구조화하지 않고 새
필드로 추가했으므로, 다이제스트 도입 이전에 기록된 실행도 그대로 읽히고 재현 가능합니다.

**이전 결과 영향.** **기록된 이전 결과의 수치는 영향받지 않습니다.** run_id 형식 변경은
앞으로 생성되는 id 에만 적용되고 기존 id 는 그대로입니다. 다이제스트가 없던 시절의 아티팩트
70개는 `verify-runs` 에서 `not_recorded` 로 보고됩니다 — 조용히 통과시키지 않는 것이
핵심이며, "검증됨"과 "검증 불가"는 다른 상태입니다. E22/E23 헤드라인 실행도 여기에
해당하고, 그 사실을 숨기지 않습니다.

**검증.** 같은 초에 만든 id 20개가 모두 다른지, 충돌이 강제되면 기존 기록이 보존된 채
거부되는지, 정상 생명주기 갱신은 여전히 동작하는지, `os.replace` 실패 시 레지스트리가
온전한지, 임시 파일이 남지 않는지, 다이제스트가 사후 수정·삭제·미기록을 각각 구분하는지,
그리고 CLI 가 수정 탐지 시 종료 코드 1 을 내는지 확인하는 테스트 10개가 통과했습니다.

## ADR-0021 — 브라우저 DOM 자막 경로는 별도 입력 계약과 별도 아티팩트를 쓴다
**상태:** 채택 (2026-08-17, Phase 4 / E30)

**맥락.** 배포 모델(`clinical_plus_confusion`, 50열)은 음향 맥락 4열을 씁니다:
`c_snr_db`, `c_speaker_male/female/unknown`. 브라우저가 그리고 있는 자막은 **텍스트만**
줍니다 — 신호대잡음비도, 화자 정체도, 측정된 ASR 신뢰도도 없습니다.

`c_snr_db = 20` 을 조용히 채우는 선택지가 있었고, 이를 기각했습니다. 측정하지 않은 값을
측정한 것처럼 보고하는 일이며, E25(§13)에 따르면 전체 개인화 이득의 6.4–13.7배가 조건 간
예산 배분에서 오므로 SNR 은 이 모델에서 장식이 아니라 이득의 주된 출처입니다. 그것을
상수로 대치하면 모델이 학습 분포 밖에서 돌고 결과가 조용히 무의미해집니다.

**결정.** 없는 정보는 추측하지 않고 **모델의 세계에서 제거**합니다. 라이브 모델은 추론 시
갖게 될 것과 같은 정보 제약 아래에서 학습합니다.

`live-caption-v1` 계약(`audire.live.contract`)이 정합니다.
* 특징 계열별 라이브 가용성과 근거. `context` 만 UNAVAILABLE 입니다.
* 이름(`c_snr_db`)과 접두사(`c_`) 양쪽으로 음향 열 차단 — 새 음향 특징이 추가돼도 먼저
  걸립니다.
* 순서를 포함한 특징 스키마 다이제스트. 선형 계수가 열 순서에 묶여 있기 때문입니다.
* `media-pipeline-v1` 과의 교차 사용 금지. 파일이 존재한다는 이유만으로 모델을 고르면
  음향 맥락을 기대하는 모델이 그것이 없는 경로에서 조용히 돕니다.

라이브 arm 은 전체 행렬을 만든 뒤 열을 지우는 방식이 **아닙니다.** `context` 블록을 애초에
포함하지 않습니다. 지우는 방식은 전처리 통계와 열 순서가 지워진 열의 존재에 의존하게 만들어
학습과 추론 스키마가 조용히 어긋날 수 있습니다.

`fit_live_artifact` 가 만드는 아티팩트는 미디어 아티팩트를 덮어쓰지 않는 별도 계열이며,
`input_contract` · `feature_schema_hash` · `artifact_type` · `intended_use` ·
`simulator_version` · `human_efficacy_evidence: false` 를 sidecar 에 기록합니다.

**선택된 arm: LIVE-2** (`live_word_context_clinical_confusion`, 46열). E30 에서 모델 품질의
모든 지표가 우세합니다(PR-AUC 0.6117 → 0.7614, Brier 0.2402 → 0.2038, ECE 0.0158 → 0.0122),
동일 자막률에서 총합 재현율 +0.067 (5/5 시드).

**강제되는 전제 조건 — 전역 임계값 금지.** E30 은 전역 임계값에서 LIVE-2 가 normal 청취자에게
자막률 0.0004, mild 에게 0.0204 를 주고 중앙값 청취자 재현율이 0 이 된다는 것을 보였습니다.
총합 이득이 분량 재배분에서 오기 때문입니다. 같은 예측에 **청취자별 임계값**을 적용하면 모든
중증도 계층이 ~0.20 자막률과 0.22–0.27 재현율을 받고 최하위 청취자가 0.2049 가 됩니다.
따라서 라이브 소비 측은 청취자별 임계값만 씁니다. 이 제약은 `fit_live_artifact` 의 docstring
에도 적혀 있습니다.

이는 §5(RQ3)가 이미 기록한 것과 같은 절충입니다. 전역 임계값은 총합 재현율이 높지만 청취자
절반이 자막을 거의 받지 못합니다.

**LIVE-0 을 고르지 않은 이유.** LIVE-0 의 형평성은 원리에서 오지 않고 **분별 불능**에서
옵니다. 16,000행에서 고유 점수가 33개뿐이라 사용자가 임계값 슬라이더를 움직여도 자막량이
계단식으로만 변하며, 그 성질이 동일 자막률 비교를 처음에 무효로 만들기도 했습니다.

**사전 선언 규칙에 대한 정직한 기록.** 다섯 기준을 문자 그대로는 모두 충족했습니다. 다만
기준 4가 "severe / 저-WRS / 저-정확도에서 붕괴 없을 것" 이었는데, severe 는 붕괴하지 않고
오히려 76% 를 받았고 붕괴는 지목하지 않은 normal/mild 에서 일어났습니다. 규칙을 사후에
고쳐 쓰지 않고, 예측이 빗나간 사실과 관측된 붕괴를 함께 기록합니다.

**이전 결과 영향.** **기록된 이전 결과는 영향받지 않습니다.** 라이브 arm·계약·아티팩트는
모두 신규이고, 미디어 경로의 기본 계약과 배포 아티팩트는 그대로입니다. 기존 arm 도 하나도
지우지 않았습니다.

**검증.** 계약·arm·아티팩트·로더 분리·동점 분할·자막률 매칭을 다루는 테스트 60개가
통과했습니다. 전체 820 통과, 커버리지 91%, `mypy --strict` 72 파일 무오류.

## ADR-0022 — 확장은 빌드 단계 없이 두고, 네트워크 출구를 서비스 워커 하나로 모은다

**상태**: 채택 (Phase 6)

**맥락.** 라이브 자막 확장(Manifest V3)의 뼈대를 세우면서 두 가지를 정해야 했습니다.
어떤 언어/도구로 쓸 것인가, 그리고 로컬 서버 요청을 누가 보낼 것인가.

### 결정 1 — TypeScript 대신 JSDoc 주석이 붙은 평범한 ESM

미션 문서는 `tsconfig.json` 이 있는 구조를 제안했습니다. 그것을 따르지 않았습니다.

TypeScript 를 넣으면 npm 의존성 트리, lockfile, CI 설치 시간, 그리고 **시험한 코드와
브라우저에 실제로 실린 코드 사이의 빌드 단계**가 함께 들어옵니다. 마지막 항목이 결정적
이었습니다. 이 저장소는 아티팩트 다이제스트와 계약 해시로 "실행된 것이 기록된 것과 같은가"
를 계속 확인해 왔는데, 확장에만 트랜스파일 결과물이 끼어들면 그 성질이 확장 경계에서
끊깁니다.

지금 확장 코드는 의존성이 0이고, `node --test` 만으로 돌며, `chrome://extensions` 에 로드
되는 파일이 시험이 읽은 파일과 **같은 파일**입니다.

**대가.** 컴파일 타임 타입 검사가 없습니다. 이것을 그냥 감수하지 않고, 타입이 잡아줬을
종류의 오류를 계약 시험으로 옮겼습니다 — 어댑터 형태 검사(`assertAdapterContract`),
매니페스트 참조 파일 존재 확인, 메시지 종류 화이트리스트. 확장이 커져서 이것으로 부족해지면
그때 재검토합니다. 판단 기준은 "타입 없이 놓친 결함이 실제로 생겼는가" 입니다.

### 결정 2 — 네트워크 출구는 서비스 워커 하나

콘텐츠 스크립트가 로컬 서버를 직접 부르지 않습니다. 이유가 셋입니다.

1. **토큰.** 콘텐츠 스크립트는 임의의 페이지 위에서 돕니다. 페어링 토큰이 거기로 내려가면
   로컬 서버의 출처 구분(ADR 없이 `live/pairing.py` 에 기록된 제약)이 무의미해집니다.
2. **CORS.** MV3 에서 콘텐츠 스크립트의 `fetch` 는 페이지 출처를 따릅니다. 재생 사이트에서
   `127.0.0.1` 로 직접 요청하면 막힙니다.
3. **순서.** 라이브 자막에서 요청은 겹치고 응답은 순서를 지키지 않습니다. 큐 A 의 응답이
   큐 B 보다 늦게 도착하면 화면이 **과거 자막으로 되돌아갑니다.** 그 판정(`stale`)이 한
   곳에 있어야 하고, 탭마다 클라이언트를 두면 흩어집니다.

**검증.** 여섯 개의 변형을 실제로 주입해 해당 시험이 실패하는 것을 확인했습니다: 토큰을
응답에 실음, 꺼짐 가드 제거, 순서 판정 제거, `<all_urls>` 추가, 루프백 검사 제거, NFC
정규화 제거. 확장 시험 42개가 통과하며 `make check` 와 CI 의 `extension` 작업에 묶였습니다.

**기본값은 꺼짐.** 설치만으로는 어떤 페이지의 자막도 읽지 않습니다. 사이트 자막을 읽는
호스트 권한도 아직 요청하지 않습니다 — 어댑터가 생기는 단계에서 해당 사이트만 들어갑니다.

## ADR-0023 — 자막은 DOM 이 아니라 전선 데이터이고, 어댑터 실패는 명시적이며, 사라짐은 별도 사건이다

**상태**: 채택 (Phase 7)

ADR-0022(평범한 ESM 유지, 네트워크 출구는 서비스 워커 하나)는 그대로입니다. Phase 7 은
그 위에 **페이지 쪽 취득 계약**을 얹습니다.

### SubtitleCue 는 DOM 객체가 아니다

큐는 콘텐츠 스크립트 → 서비스 워커 → 로컬 서버로 건너갑니다. 그 경계를 넘는 값에 DOM
객체가 섞이면 조용히 망가집니다. `DOMRect` 의 좌표 여덟 개는 프로토타입의 접근자이지 자기
속성이 아니어서 `{...rect}` 가 `{}` 가 됩니다. 메시지를 조립하다 전개 한 번이면 좌표가
통째로 사라지고 아무 오류도 나지 않습니다.

`DOMRect` 에는 `toJSON` 이 있어 `JSON.stringify` 는 통과합니다. **직렬화 검사로는 걸러지지
않습니다.** 그래서 `assertCaptionRect` 는 속성 서술자를 봅니다 — 자기 데이터 속성이
아니면 거절합니다. 같은 이유로 `assertSubtitleCue` 는 모르는 열쇠를 거절하며, 그것이
Element 가 `cue.node` 같은 이름으로 들어오는 경로를 막는 축입니다.

`snapshotRect` 는 값을 복사합니다. 큐가 대기하는 동안 페이지가 스크롤되어도 큐가 든 것은
관측 시점의 위치여야 합니다. 잴 수 없으면 `null` 이고, 그러면 `boundingRect` 없이
나갑니다. 0 으로 채우면 "화면 맨 위" 라는 뜻이 됩니다.

### 어댑터 실패는 명시적이다

`selectAdapter` 는 어댑터 대신 상태를 돌려줍니다. `null` 이면 호출자가 "아직 안 읽었음"
"자막 없음" "지원 안 함" 중 무엇으로든 해석할 수 있는데, 그 셋은 사용자에게 전혀 다른
뜻입니다. 특히 이 둘을 뭉치면 안 됩니다.

* `NO_MATCHING_ADAPTER` — 이 사이트는 애초에 대상이 아닙니다. 사용자가 할 일이 없습니다.
* `SUBTITLE_ROOT_NOT_FOUND` — 어댑터는 안다고 했는데 뿌리가 없습니다. 자막이 꺼졌거나
  **선택자가 낡았습니다.** 후자는 유지보수 신호이며, 뭉개면 영영 보이지 않습니다.

뿌리를 못 찾으면 그것으로 끝입니다. 비슷한 요소를 찾아 나서지 않습니다. 픽스처 어댑터의
뿌리 탐색이 한 줄뿐인 것도 같은 이유입니다 — 대안 선택자를 나열해 두면 첫 번째가 낡았을
때 두 번째가 조용히 받아내고, 낡았다는 사실이 드러나지 않습니다.

### 픽스처 어댑터가 계약의 참조 구현이다

실제 사이트 선택자를 쓰기 전에 계약 전체가 결정적으로 도는지 증명하는 자리입니다.
픽스처 페이지에는 제목·설명·댓글에 자막처럼 생긴 한국어를 일부러 깔았습니다. 어댑터가
뿌리를 놓쳤을 때 "비슷한 것" 으로 흘러가면 그 문장들을 읽게 되고, 시험이 그것을 잡습니다.

`matches` 는 경로만 보지 않습니다. 원격 사이트가 같은 경로를 흉내 내면 개발용 어댑터가
사용자의 실제 시청 페이지에 붙습니다. `file:` 이거나 루프백 http 여야 합니다.

### 관찰자는 논리적 자막을 중복 없이 내보낸다

MutationObserver 는 보이는 자막 하나에 대해 수십 번 발화합니다. 지문은 **정규화된 보이는
텍스트**이며 관측 시각을 담지 않습니다. 시각이 섞이면 모든 읽기가 새 큐가 되어 억제가
통째로 무력해집니다.

**디바운스를 넣지 않았습니다.** MutationObserver 는 이미 브라우저가 마이크로태스크에서
묶어 전달하고, 그 위에 지문 비교가 얹힙니다. 타이머를 더하면 짧게 스쳐가는 자막이 한
번도 관측되지 않고 사라집니다. 대사가 빠른 구간이 통째로 비는 쪽이, 요청 몇 번 더 나가는
쪽보다 나쁩니다.

지문은 **마지막에 내보낸 것**과만 비교합니다. 본 적 있는 문장을 전부 기억하면 반복되는
대사가 두 번째부터 영영 나오지 않습니다.

### 사라짐은 빈 큐가 아니다

자막이 사라지는 것은 상태 변화입니다. 빈 문자열을 채점하러 보내면 서버는 그것을 잘못된
입력으로 거절하고(`validate_cue`), 화면은 지워지지 않습니다. 별도의 clear 사건으로
정확히 한 번 나갑니다.

### 뿌리 수명 — 보고하고 멈춘다

SPA 는 자막 컨테이너를 통째로 다시 만듭니다. **설계 A 를 골랐습니다**: 관찰자가
`ROOT_STALE` 을 보고하고 멈추며, 다시 붙이는 것은 호출자의 몫입니다. 관찰자가 스스로
`document` 를 뒤지지 않습니다.

관찰 대상은 뿌리의 **부모**입니다. 뿌리 자신만 보면 뿌리가 제거될 때의 childList 변경은
부모에서 일어나므로 영영 발화하지 않고, 관찰자는 조용히 죽은 채로 남습니다. 부모까지
올라가는 것이 뿌리 수명을 볼 수 있는 최소 범위입니다.

### 검증

변형 여덟 개를 주입해 각각 해당 시험이 실패하는 것을 확인했습니다: NFC 정규화 제거,
중첩 span 을 공백으로 이어붙임, 지문에 관측 시각을 섞음, 중복 억제 제거, clear 를 빈 큐로
바꿈, 픽스처 어댑터가 모든 호스트에 붙음, 스냅숏 대신 DOMRect 를 실음, 뿌리가 없을 때
페이지 본문을 읽음.

Node 의 손수 만든 DOM 에서 얻은 결론을 **실제 브라우저에서 다시 확인했습니다.** 로컬
서버로 픽스처를 띄우고 진짜 `MutationObserver` 로 같은 순서를 돌린 결과가 동일했습니다:
같은 문장에 대한 DOM 변경 20회 → 큐 1개, 문장 교체 → 큐 1개, 제거 → clear 1개, 뿌리
제거 → `root_stale` 1개, 정지 후 → 무출력. 큐의 `boundingRect` 는 자기 속성 8개를 가진
평범한 객체였고 JSON 왕복을 견뎠습니다.

그 확인 과정에서 픽스처 페이지의 결함도 하나 나왔습니다. 조작기를 `type="module"` 로
불렀는데, 모듈 스크립트는 `file://` 에서 CORS 로 막힙니다. 어댑터는 `file:` 을 지원한다고
하면서 정작 그 경로에서는 페이지가 죽는 상태였습니다. import 가 없는 파일이므로 평범한
스크립트로 바꿨습니다. 다만 이 환경에서 실제로 확인한 것은 루프백 http 뿐이고,
`file://` 은 구조상 동작하지만 확인되지 않았습니다.

### 부수적으로 잡힌 결함 — 원본 속의 날 NUL 바이트

Phase 6 에서 `cueFingerprint` 의 구분자 자리에 **보이지 않는 NUL 바이트**가 들어가 있었
습니다. 화면에도 diff 에도 보이지 않았고, 동작이 우연히 맞아서 시험 42개가 전부
통과했습니다. Phase 7 에서 그 줄에 변형을 넣으려다 문자열이 일치하지 않아 드러났습니다.

escape 표기로 바꾸고, 원본 전체에서 날 제어문자를 금지하는 시험을 넣었습니다. 그 시험은
자기 자신의 주석에 남아 있던 두 번째 NUL 을 곧바로 잡았습니다. 보이지 않는 문자는
리뷰로 잡을 수 없습니다.

구분자로 NUL 을 쓰는 것 자체는 의도된 선택입니다. 공백이면 (출처 "a", 문장 "b c") 와
(출처 "a b", 문장 "c") 가 같은 지문이 됩니다.

### 아직 없는 것

실제 YouTube 어댑터, OTT 어댑터, 실제 사이트용 콘텐츠 스크립트, 화면 렌더링, 그리고
사이트 호스트 권한. 매니페스트의 호스트 권한은 여전히 로컬 서버뿐입니다.

## ADR-0024 — 페이지 배선: 꺼짐은 읽지 않는 것이고, 순서는 화면마다이며, 토큰은 페이지에 닿지 않는다

**상태**: 채택 (Phase 8)

Phase 7 이 "어댑터가 자막이라고 지목한 노드를 결정적으로 관찰할 수 있는가" 를 증명했다면,
Phase 8 은 그것을 확장의 나머지와 잇습니다.

```
페이지 → 어댑터 선택 → 관찰자 → 서비스 워커 → 로컬 서버
```

여전히 **픽스처 페이지에만** 붙습니다. 실제 사이트 어댑터도, 실사이트 호스트 권한도
없습니다.

### 꺼짐은 "읽고 나서 버리는 것" 이 아니다

서비스 워커도 꺼짐을 막습니다(Phase 6). 그러나 그 지점에서는 자막 텍스트가 **이미 확장
안으로 들어온 뒤**입니다. 제어기는 꺼져 있으면 어댑터조차 고르지 않고 관찰자를 시작하지
않습니다. 페이지를 읽지 않는 것과 읽고 나서 버리는 것은 다릅니다.

기본값이 꺼짐이므로, 설치 직후의 기본 상태에서 확장은 어떤 페이지도 읽지 않습니다.

### 순서는 화면마다다 — 실제 결함이었다

서비스 워커는 `AudireClient` 를 **하나만** 둡니다. 순번이 하나의 숫자였을 때, 탭이 둘이면
두 화면의 큐가 같은 카운터를 나눠 씁니다. 탭 A 의 응답이 탭 B 보다 늦게 도착했다는 이유로
A 의 자막이 버려집니다 — 서로 다른 화면인데도.

Phase 6 에서는 탭이 하나뿐이라 드러날 수 없었고, 콘텐츠 스크립트를 붙이는 이 단계에서
비로소 실재하게 되었습니다. 순번을 `streamId` 별로 나눴습니다. `streamId` 는 확장 안에서만
쓰는 값이며 **서버로 보내지 않습니다** — 서버가 알 필요가 없고, 시청 맥락을 늘릴 이유도
없습니다.

`stale` 은 `ok` 와 독립적으로 존중됩니다. "지난 자막을 화면에 올리지 않는다" 는 화면 쪽
불변식이고 제어기가 화면 쪽입니다. 서비스 워커가 stale 을 `ok:false` 로도 표시한다는
사실에 기대면, 그 결합이 끊어지는 날 조용히 무너집니다. (이 점은 변형 시험에서 실제로
드러났습니다. 처음 쓴 시험이 `ok:false` 를 함께 주는 바람에 `!ok` 분기가 stale 검사를
가려, 검사를 통째로 지워도 시험이 통과했습니다.)

### 설정 변경은 방송으로 받는다 — storage.onChanged 가 아니라

콘텐츠 스크립트가 `chrome.storage.onChanged` 를 들으면 안 됩니다. 그 이벤트는 **바뀐 모든
열쇠의 새 값**을 실어 오고, 거기에는 페어링 토큰이 들어 있습니다. 임의의 페이지 위에서 도는
코드에 토큰을 내려보내게 됩니다.

대신 서비스 워커가 설정 저장 후 탭에 "바뀌었다" 만 방송합니다. **값을 싣지 않습니다** —
콘텐츠 스크립트는 다시 물어보면 됩니다. 이 배선 덕분에 팝업의 토글이 새로고침 없이
반영됩니다. 껐는데 탭을 새로 고쳐야 멈춘다면 그것은 꺼진 것이 아닙니다.

### 뿌리 재획득은 제어기의 몫이고, 유한하다

관찰자는 `ROOT_STALE` 을 보고하고 멈춥니다(ADR-0023, 설계 A). 다시 붙이는 것은 제어기가
합니다. 정해진 횟수(기본 5회)만 시도하고 포기하며, 붙는 데 성공하면 예산이 회복됩니다.
`document` 를 영원히 뒤지지 않습니다.

### 콘텐츠 스크립트는 모듈을 동적으로 부른다

매니페스트가 선언하는 콘텐츠 스크립트는 평범한 스크립트이며 `import` 문을 쓸 수 없습니다.
번들러를 들이면 "브라우저에 실린 코드 == 시험한 코드" 가 깨집니다(ADR-0022). 그래서
`content-loader.js` 만 평범한 스크립트로 두고, 실제 코드는 `chrome.runtime.getURL` +
동적 `import` 로 부릅니다. 불러오는 파일은 Node 시험이 읽는 것과 같은 파일입니다.

그 대가로 `web_accessible_resources` 가 필요합니다. 노출되는 것은 확장 자신의 `src/*.js`
뿐이고, 열리는 출처는 루프백뿐이며, 두 가지 모두 시험이 고정합니다.

### 검증

변형 열 개를 주입해 각각 해당 시험이 실패하는 것을 확인했습니다: 꺼져 있어도 관찰 시작,
큐 id 에 자막 실음, 오래된 응답을 화면에 반영, 뿌리 재획득 무한 반복, 설정 방송 무시,
순서 판정이 화면을 구분하지 않음, 화면 식별자를 서버로 보냄, 설정 방송에 값을 실음,
콘텐츠 스크립트를 모든 사이트에 주입, 웹 접근 자원을 모든 출처에 엶.

실제 브라우저에서 제어기·관찰자·어댑터를 진짜 `MutationObserver` 와 함께 돌린 결과가
Node 와 동일했습니다: 꺼진 동안 채점 요청 0·어댑터 선택 없음, 켜짐 방송 후 즉시 1,
같은 문장 DOM 20회 변경 후에도 +1, 문장 교체 +1, 제거 → clear 1회이며 채점 요청 없음,
뿌리 재생성 후 다시 붙어 +1. 큐 id 는 `tab-…:N` 형태로 자막을 담지 않았습니다.

### 확인하지 못한 것

**매니페스트 선언 자체(콘텐츠 스크립트 주입, `web_accessible_resources`, 동적 import)는
이 환경에서 검증하지 못했습니다.** 압축해제된 확장을 실제 Chrome 에 적재해야 하며, 그것은
Phase 13 의 수동 스모크에서 확인합니다. 지금까지 확인된 것은 모듈들이 실제 브라우저에서
실제 DOM 을 상대로 올바르게 동작한다는 것까지입니다.

`file://` 로 여는 경로도 확인하지 못했습니다. 콘텐츠 스크립트 선언은 루프백 http 만
대상으로 두었습니다 — 검증할 수 있는 범위로 좁힌 것입니다.

# AUDIRE Live — 브라우저 확장 (Manifest V3)

브라우저가 **이미 화면에 그리고 있는** 자막을 읽어, 로컬 AUDIRE 가 그 청취자에게 위험하다고
판단한 단어만 보여줍니다.

> 연구·접근성 소프트웨어이며 의료기기가 아닙니다. 학습 아티팩트는 합성 데이터에서 나왔고,
> 사람의 청취 이득에 대한 근거가 아닙니다.

## 이 확장이 하지 않는 것

- 보호된 영상·음성 스트림을 내려받거나 추출하지 않습니다.
- DRM 을 우회하지 않습니다.
- 페이지에 노출되지 않은 자막 API 를 몰래 호출하지 않습니다. 화면에 이미 보이는 텍스트만
  읽습니다.
- 자막을 저장하지 않습니다. 로컬 서버도 자막 내용을 로그에 남기지 않습니다.

## 현재 단계 (Phase 6 — 스켈레톤)

지금 있는 것은 **뼈대와 그 뼈대가 지켜야 할 규칙의 시험**입니다. 아직 어떤 사이트의 자막도
읽지 않습니다 — 콘텐츠 스크립트가 없고, 등록된 어댑터도 없습니다.

```
manifest.json          MV3 선언. 호스트 권한은 로컬 서버뿐입니다.
src/
  background.js        서비스 워커. 확장의 유일한 네트워크 출구.
  messages.js          내부 메시지 어휘 (부작용 없음).
  settings.js          설정과 페어링 토큰 보관소. 기본값은 꺼짐.
  bridge/audireClient.js   로컬 API 클라이언트. 큐 순서 판정이 여기 있습니다.
  adapters/types.js    사이트 어댑터 계약과 자막 텍스트 읽기 규칙.
  adapters/registry.js 어댑터 등록과 선택. 맞는 것이 없으면 null.
  popup/               연결·프로파일·자막량 UI.
tests/                 위 규칙들의 시험. 의존성 없이 `node --test` 로 돕니다.
```

들어올 자리만 만들어 둔 것: `src/observer/`(MutationObserver), `src/renderer/`(동반 자막
표시), `fixtures/`(로컬 재현용 자막 페이지).

## 실행

로컬 서버가 먼저 떠 있어야 합니다.

```bash
make live-model   # 라이브 계약 아티팩트가 없으면 한 번
make run
```

확장은 `chrome://extensions` → 개발자 모드 → "압축해제된 확장 프로그램을 로드"에서 이
디렉터리를 지정해 넣습니다. 팝업에서 **페어링 → 프로파일 선택 → 켜기** 순으로 진행합니다.

## 시험

```bash
npm test
```

의존성이 없습니다. `node --test` 만 씁니다. 그래서 lockfile 도, 설치 단계도, 시험한 코드와
배포되는 코드 사이의 빌드 단계도 없습니다.

시험이 고정하는 것은 문법이 아니라 **경계**입니다.

| 시험 | 막는 사고 |
| --- | --- |
| `manifest.test.js` | 권한이 조용히 넓어지는 것. `<all_urls>`, 와일드카드 호스트, 검토되지 않은 권한, 완화된 CSP, 존재하지 않는 파일 참조 |
| `background.test.js` | 페어링 토큰이 응답에 실려 콘텐츠 스크립트까지 내려가는 것. 꺼짐 상태에서 자막이 서버로 나가는 것. 원격 주소가 설정에 들어가는 것 |
| `bridge.test.js` | 오래된 큐 응답이 새 자막을 덮어써 화면이 과거로 되돌아가는 것. 실패 사유가 "안 됨" 하나로 뭉개지는 것 |
| `adapters.test.js` | 중첩 span 을 공백으로 이어 "안녕"이 "안 녕"이 되는 것. 맞는 어댑터가 없을 때 비슷한 요소를 읽고 성공한 척하는 것 |

이 시험들은 **실제로 깨지는지** 확인했습니다. 토큰 유출·꺼짐 가드 제거·순서 판정 제거·
전 사이트 권한·루프백 검사 제거·NFC 정규화 제거의 6개 변형을 넣었을 때 각각 해당 시험이
실패했습니다.

## 권한

| 권한 | 이유 |
| --- | --- |
| `storage` | 설정과 페어링 토큰 |
| `http://127.0.0.1/*`, `http://localhost/*` | 로컬 AUDIRE 서버 |

사이트 자막을 읽는 권한은 **아직 없습니다**. 어댑터가 생기는 단계에서 그 사이트만
`content_scripts.matches` 에 들어갑니다. `<all_urls>` 는 시험이 막습니다.

## 토큰

페어링 토큰은 서비스 워커와 `chrome.storage.local` 에만 있습니다. 팝업은 "연결됨/안 됨"만
알고, 콘텐츠 스크립트는 아무것도 모릅니다. 콘텐츠 스크립트는 임의의 페이지 위에서 도는
코드이므로, 거기로 토큰이 내려가면 로컬 서버의 출처 구분이 무의미해집니다.

이것은 **로컬 기기 안에서의 출처 구분**이지 인증 체계가 아닙니다. 같은 사용자 계정으로
기기에 접근할 수 있는 프로그램은 토큰 파일도 읽을 수 있습니다.
